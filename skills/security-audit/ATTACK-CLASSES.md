# 攻撃分類

#### 第1段階の結果から分類を選び、担当を分ける

アプリケーションの種類に合う分類を選びます。すべての分類がすべてのコードベースに当てはまるわけではありません。以下を出発点に、第1段階で対象固有の分類を加え、大規模な対象はサブシステムごとに分割します。脆弱性の発見、検証、修正案、優先順位付けを目的とします。検証はソースレビューと範囲を制限したローカルフィクスチャに留め、攻撃ペイロードの連鎖を作成したり、稼働中サービスの可用性を試したり、共有環境を操作したりしないでください。

ソースの証拠と限定した検証で境界全体と意味のある結果を示せる場合だけ `confirmed` にします。デプロイ、プロバイダー、プラットフォーム、ID、実行時の特定の事実が不明なら `needs_validation` にし、不明点と、それを解決する安全なローカル検査または所有者による観測を明示します。

> **ネイティブ／バイナリ／カーネル**：C/C++/Rust の unsafe、カーネルモジュール、パーサー、デコーダー、FFI、並行ランタイム、ローダー、JIT、ファームウェアには [MEMORY-SAFETY-AND-BINARY.md](MEMORY-SAFETY-AND-BINARY.md) のメモリ安全性、整数／ABI、並行処理、ローダー、特権インターフェースの分類を使います。
>
> **AI／LLM／エージェント**：チャットボット、RAG、永続メモリ、ツール呼び出し、MCP、プロンプト構築、モデルによる操作には [AI-AND-LLM.md](AI-AND-LLM.md) のコンテキスト、メモリ汚染、操作の結び付け、スキーマ、MCP ID、出力の分類を使います。
>
> **HTTP／Web／認証**：Web アプリ、API、リバースプロキシ、CDN、ゲートウェイ、独自 HTTP パーサー、セッション、CSRF、JWT、OAuth/OIDC、SAML、MFA、パスキー、アカウント回復・連携、API キー、mTLS には [WEB-PROTOCOL-AND-AUTH.md](WEB-PROTOCOL-AND-AUTH.md) を使います。
>
> **クライアント／ブラウザー**：SPA、拡張機能、WebView、Service Worker、ブラウザーストレージ、ウィンドウ間通信、CORS、WebSocket、DOM 表示には [CLIENT-SIDE.md](CLIENT-SIDE.md) を使います。
>
> **サプライチェーン／リリース**：依存解決、生成入力、CI、リリース・署名・昇格、更新、プラグイン、拡張機能には [SUPPLY-CHAIN-AND-RELEASE.md](SUPPLY-CHAIN-AND-RELEASE.md) を使います。
>
> **クラウド／デプロイ**：IAM、IaC、コンテナ／Kubernetes、サービスメッシュ、サーバーレス／エッジ、入口経路、プロバイダーイベント、実行時設定には [CLOUD-AND-DEPLOYMENT.md](CLOUD-AND-DEPLOYMENT.md) を使います。
>
> **プロトコル／RPC／メッセージング**：gRPC、GraphQL トランスポート、Protobuf/Cap'n Proto/Thrift、独自プロトコル、キュー、ブローカー、pub/sub、Webhook、ストリーミング RPC には [PROTOCOLS-RPC-AND-MESSAGING.md](PROTOCOLS-RPC-AND-MESSAGING.md) を使います。
>
> **資源枯渇／可用性**：非信頼の処理が共有 CPU、メモリ、ディスク、接続、ワーカー、キュー、クォータ、運用費を消費する場合は [RESOURCE-EXHAUSTION-AND-AVAILABILITY.md](RESOURCE-EXHAUSTION-AND-AVAILABILITY.md) を使います。
>
> **データ分離／ライフサイクル**：マルチテナント保存、キャッシュ・検索、オブジェクトリンク、分析、エクスポート・バックアップ、移行、削除、保持、復元には [DATA-ISOLATION-AND-LIFECYCLE.md](DATA-ISOLATION-AND-LIFECYCLE.md) を使います。
>
> **デスクトップ／モバイル／ローカル IPC**：ネイティブアプリ、ディープリンク、WebView ブリッジ、公開コンポーネント、特権ヘルパー、デーモン、Unix ソケット／XPC／Binder／D-Bus には [DESKTOP-MOBILE-AND-LOCAL-IPC.md](DESKTOP-MOBILE-AND-LOCAL-IPC.md) を使います。

**Injection**（インジェクション）（subagent_type: `general`）
信頼できない入力を入口から危険な処理先（sink）まで追います。処理先は対象によって異なります。

- Web：SQL、HTML 出力、シェル、テンプレート、ファイルパス、HTTP リダイレクト、デシリアライズ
- ライブラリ：未検証の呼び出し側データを扱うバッファー操作、パーサー、書式文字列など
- CLI：シェルコマンド構築、パス処理、環境変数の展開
- サービス：クエリ構築、メッセージのシリアライズ、ログ、LDAP/XPATH
- ブラウザー／JS：DOM XSS、プロトタイプ汚染、`postMessage` と origin の信頼など。選択した [CLIENT-SIDE.md](CLIENT-SIDE.md) の補足ブロックで扱います。

直接の経路だけで終えず、安全に保存したデータが別コードによって危険な文脈で再利用される間接経路を探します。値だけでなくフィールド名、キー、ヘッダー、メタデータ、ログ・キャッシュ・検索索引・分析などの二次システムも確認します。

**Access control**（アクセス制御）（subagent_type: `general`）
呼び出し側が権限外の操作をできないことを確認します。検査の有無だけでなく、正しい仕組みで、正しいリソースの、正しい権限を確認するか調べます。

- 同じ状態変更に、別の弱い権限検査を使う経路はないか。
- リクエスト本文で権限制限を上書きできないか。
- 認証だけ行い認可を忘れたエンドポイントはないか。
- 同じリソースへの複数経路で検査が不一致になっていないか。
- 一括・バッチ・エクスポート・インポートで項目ごとに認可するか。

複雑なモデルでは認証回避と認可ロジックを別エージェントへ分けます。

**Resource and file handling**（リソース・ファイル処理）（subagent_type: `general`）

- パストラバーサル：意図した外への読み書き。シンボリックリンク、符号化列、NUL バイトも確認します。
- SSRF：攻撃者指定 URL の取得。リダイレクト、DNS リバインディング、URL パーサーの差も確認します。
- 危険なデシリアライズ、アーカイブ展開（Zip Slip）、一時ファイル処理
- 該当する場合のバッファーオーバーフロー、解放後使用、整数オーバーフロー
- ファイル検査と利用の間の競合（TOCTOU）

**Cryptography and secrets**（暗号・秘密情報）（subagent_type: `general`）

- トークン、鍵、nonce の弱い乱数
- 埋め込まれた秘密や、ログ、エラー、URL、クライアント応答への秘密の混入
- 不正な鍵導出、HMAC 検証欠落、nonce 再利用
- 秘密比較のタイミングサイドチャネル
- ECB、認証なし暗号、固定 IV などの誤用
- 暗号処理失敗時に暗号なしへフォールバックしないか。

**Business logic**（業務ロジック）（subagent_type: `general`）
一般的なスキャナーでは見つけにくく、影響の大きい論理的欠陥を手作業で調べます。主要な処理ごとに確認します。

- **状態遷移の違反**：手順の省略、逆行、不正状態、完了済みの再実行。3段階中の2段階目が失敗したら1段階目を戻すか。
- **業務に影響する競合**：二重支払い、二重承認、更新消失。非原子的な検査後実行を重点確認します。
- **数値・数量の操作**：負数、ゼロ、桁あふれ、精度損失、文字列と数値の型変換。
- **アクセス境界の違反**：業務規則に合う検査か。同じ効果を持つ別操作の制限を入力で回避できないか。
- **暗黙の信頼**：「入口で検証済み」として保存データ、設定、別コンポーネント、プラグインを信頼していないか。別の書き込み経路を考えます。
- **時刻のロジック**：期限、予約、レート窓、時刻ずれ、ちょうど境界の瞬間、コンポーネント間のタイムゾーン差。
- **既定・フォールバック**：設定欠落、機能フラグ無効、依存停止、移行途中での安全性。

**Feature abuse and data leakage**（機能の悪用・データ漏えい）（subagent_type: `general`）
正規機能の意図しない使用を、実装だけでなく設計から調べます。

- **エクスポート／バックアップによる持ち出し**：低権限で他人や権限外のデータ、削除済み・下書き・非公開の内容、除去予定の履歴まで出力できないか。
- **インポート／復元による注入**：既存データの上書き、通常検証の回避、書き込み権限のないコレクションへの追加。UI と同じ認可モデルか。
- **検索／絞り込み／並び替えを使った推測**：直接読めない内容の存在、非公開の状態・役割・項目、非表示フィールドの値が結果や順序から分からないか。
- **副作用による列挙**：「存在しない」と「権限がない」のエラー、応答時間・サイズ・HTTP 状態の差。パスワード再設定、招待、登録でユーザーを列挙できないか。
- **プレビュー／下書き／ステージングの漏えい**：プレビュートークンが1件を越えて権限を与えないか。検索、RSS、サイトマップ、一覧 API、CDN キャッシュから非公開内容が漏れないか。
- **通知／Webhook による SSRF**：通知・Webhook・コールバック URL の内部ネットワーク制限は有効か。リダイレクト後も検査するか。

**Chained vulnerabilities and trust boundaries**（脆弱性の連鎖・信頼境界）（subagent_type: `general`）
単独では許可・封じ込められた挙動でも、別コンポーネントや後の処理がより強い保証を前提にすると脆弱性になります。

- **複数手順の境界破綻**：低権限主体の読み書き、呼び出し、保持を整理し、具体的な出力だけを後段の判断につなげます。各前提を確認し、後段の影響を仮定しません。
- **コンポーネント間の信頼の隙間**：A が保証するものと B の前提を、切り詰め、型変換、正規化、テナント範囲、拡張機能の権限まで比較します。
- **二次利用**：保存時に安全でも、項目名が JSON パス、slug がファイルパス、エスケープ済み文字列が生の表示、保存文字列が URL・正規表現・テンプレート・ポリシー式になる経路。
- **範囲・機能の拡大**：トークン、API キー、プラグイン、OAuth、MCP、AI の権限が委譲、更新、キャッシュ、役割変更、組み合わせで増えないか。許されない具体的操作を示します。
- **時間・順序**：初期設定、移行、論理削除、失効／キャッシュ期限、検査／利用、検証／消費の隙間。古い状態が実際に受理されることを確認します。
- **巻き戻し・復旧**：削除取消、復元、版の巻き戻し、キャンセルでも現在の所有権、検証、認可を適用するか。不正な復元状態を特定します。

**Wildcard**（分類外の探索）（subagent_type: `general`）
既存分類で割り当てていない脆弱性を探します。退屈に見えるコードや、セキュリティに無関係に見えるコードも読みます。未完成、実験的、互換、フォールバック機能でも、他の分類と同じ具体的な境界・検証条件を守ります。

- 最も奇妙なコードは何か。なぜ存在し、悪用するとどうなるか。
- 未完成・実験的・後付けに見える機能はないか。レビューが少なくなりがちな箇所を確認します。
- フロントエンドが行わない API 操作は何か。UI の制限を API が強制するか。
- 未公開のエンドポイント、引数、ヘッダー、機能をルート登録、ミドルウェア、設定から探します。
- 多言語化＋プレビュー＋キャッシュ、インポート＋プラグイン＋Webhook、OAuth＋代理ログイン＋API キーなど、想定外の組み合わせを調べます。
- Git 履歴の取り消された修正、コメント化された認証、削除済みでも履歴に残る秘密を確認します。
- 正規アカウントのどの操作が他人、共有の完全性・可用性、運用費に影響するか。隔離、クォータ、認可、復旧を確認します。
- 不可逆または追加確認が必要な操作で、認可と承認を最終的な主体・操作・リソースに固定するか。
- DB がローカル、時計が正確、DNS が信頼可能、ファイル名が大文字小文字を区別するなどの環境前提はないか。
- テストが確認していないことは何か。開発者が考えた境界条件と、考えていない境界条件を比較します。

担当範囲の異常は、不変条件が明確になるまで追います。安全に見える理由のコメントは検証し、`temp`、`hack`、`legacy` といった変数名は注意して読みます。

**Obvious things**（基本事項の確認）（subagent_type: `general`）
他の担当が微妙な欠陥を探す間、誰かが確認済みと思われがちな基本的露出を確認します。

- 埋め込みのパスワード、API キー、トークン、秘密。`password`、`secret`、`apikey`、`token`、`Bearer`、`-----BEGIN`、よくある初期パスワードを検索します。
- セキュリティに関わる TODO/FIXME/HACK/XXX。`TODO: add auth`、`FIXME: validate input`、`HACK: skip permission check` など。
- デバッグ／開発モードの制限。本番で環境変数、クエリ、ヘッダーから有効化できないか。
- 本番でも使えるテスト・サンプル・初期投入用の認証情報。
- 保護されていない `/debug`、`/admin`、`/test`、`/status`、`/health`、`/metrics`、`/env`、`/.env`、`/config`。
- コミットされた `.env`、`.env.local`、`credentials.json`、`*.pem`、`*.key`。
- `.gitignore` が秘密、アップロード、ローカル設定を実際に除外するか。
- 依存バージョンの固定と既知 CVE。ロックファイルを確認します。
- 動的入力を使う `eval()`、`exec()`、`child_process`、`Function()`、`vm.runInContext`、`import()`。
- `*` など過剰な CORS 許可、ワイルドカード origin と `Access-Control-Allow-Credentials` の併用。
- Cookie の `HttpOnly`、`Secure`、`SameSite` 欠落。
- `redirect`、`return`、`next`、`url`、`goto`、`continue` が未検証で転送先になるオープンリダイレクト。
- TLS の強制、HTTP だけのエンドポイント。
- 本番エラーでのスタックトレース、内部パス、SQL エラーの開示。

創意よりも漏れなく文字どおり確認することを重視し、全項目の結果を報告します。

**Important**（重要）：見た目だけでなく経路全体を検証します。`HttpOnly` がなくても、Cookie が機密を含むか、設計上 JS で読む必要があるかを確認します。エラーの項目名だけでなく、その項目に機密が実際に入るかを確認します。フラグの欠如だけを指摘せず、影響まで追ってから報告します。
